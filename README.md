## Download / build

Windows x64 builds and tests run **on GitHub Actions**, not on the owner's laptop. Open the latest successful [Windows native UI run](https://github.com/sansaks-jpg/rustmix/actions/workflows/windows.yml) and download `rustmix-windows-x64`. Extract and run `rustmix.exe`. This is an unsigned portable prototype, not an installer.

`rustmix-ui-evidence` contains native rendered screenshots and smoke-state JSON when the graphics environment supports launch. A build is not accepted as a successful UI milestone until that smoke step passes.

Latest verified prototype: [75 passing tests and native Windows acceptance](https://github.com/sansaks-jpg/rustmix/actions/runs/39111788801), runtime revision `a01f498`. Developer commands (for CI / an authorized build machine with Rust 1.94.1 and Windows MSVC tools):

```text
cargo fmt --all -- --check
cargo check --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings

cargo build --release --workspace --locked
```

## Operate the demo

Seven synthetic inputs are available on launch. Select an input thumbnail to change Preview. Space cuts, Enter fades, and the T-Bar scrubs a manual crossfade. The source exchange commits at completion; cancel returns to the original Program. B fades to black / restores. F1–F4 toggle Program overlays. Text editing suppresses switching shortcuts.

Add Input supports seven procedural types and PNG images. Unsupported device/network/media categories are disabled; no MP4 or other video decoder is present. Generator samples are named as generators, and unsupported files cannot silently become synthetic inputs. Per-tile Cut explicitly takes that source to Program. Per-tile 1–4 buttons use its name as a lower-third title, rather than overlaying the full video input. Quick Play cuts the already animating synthetic Preview; Pause Inputs freezes procedural video while transitions remain responsive. Input Edit opens rename, color, type and online/offline properties. Removing Program/Preview or editing sources during a transition is rejected explicitly. Offline inputs render black and stay in the project with a warning.

The source selector now groups seven implemented procedural generators alongside explicitly disabled media/device categories. Input Properties separates General, staged simulated Audio routing, and Source status; source removal requires confirmation. Settings groups display, appearance, workspace and shortcuts with a draft Apply/Cancel flow for project preferences and layout presets. Checkpoint recovery runs when requested; mixer-strip changes apply immediately; Input Settings applies its audio draft with OK. UI-009 acceptance now covers hosted native screenshots and tests for this workflow. Physical device/DPI qualification remains open.

Audio strips control gain, mute, solo and Master/Aux A/Aux B assignments. **Meters are deterministic simulations; no audio is emitted.** Bus mute and solo affect simulated bus meters. There is no mix-minus DSP or hardware device backend.

The main layout follows common vMix-style placement: orange Preview, green Program, centered transition stack, inputs below, audio on the right and production controls along the bottom. All code/media/branding remain independent. Drag the lower panel tabs to rearrange, dock or float them inside the main window. Drag dividers and the lower edge of the monitor bank to resize. View restores Production / Audio focus presets. Multiview changes the main monitor area into source tiles. Fullscreen applies to the application window, not a separate video output.

Save / Save As writes versioned `.rustmix.json` project JSON with the panel layout. Open restores it. Files are validated and replaced atomically on the same filesystem; `.bak1` / `.bak2` retain previous versions and `.bak0` is a recovery journal. Existing corrupt projects are not overwritten. File dialogs and disk operations run on a worker so the demo remains responsive. Automatic recovery checkpoints are written every 60 seconds to the user's application data RustMix folder; use Settings → Recover checkpoint. Project files are not silently restored at launch. Window geometry and panel placement are persisted by eframe.

Canvas resolution is a project preference; the UI demo raster is capped at 640×360 and source previews at 384×216. CPU demo generation time and UI callback FPS are measured; they are not broadcast output, encoder, GPU or end-to-end latency metrics.

UI-004 through UI-006 refine the broadcast operator workflow across all four bounded dialogs (`Add Input`, `Input Properties`, `Settings`, and `Overlay Settings`): left-aligned sidebar navigation with procedural vector icons, fixed Apply/Cancel footers, staged per-slot `Overlay Settings` with a normalized 16:9 placement preview, visual shortcut keycap cards, direct per-input audio routing shortcuts (`⚙` on mixer strips and `"Audio Settings…"` on Input Properties), toolbar dropdown carets (`Open ▼`, `Save As ▼`, `Settings ▼`), graduated horizontal T-Bar scale marks, broadcast-dark dock tabs, and `Multiview` Split/Grid layout presets.
