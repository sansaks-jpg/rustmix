# RustMix

Independent Rust native live-production switcher. **Experimental synthetic desktop UI**, not a broadcast-ready product. No affiliation with vMix. No capture devices, encoders, real audio, recording or streaming backends are implemented.

The desktop UI uses eframe/egui and wgpu. The headless engine owns typed commands, Program/Preview, transition timing, input properties, simulated audio controls and project validation. All demo images are generated by original Rust code.

## Download / build

Open the latest successful [Windows native UI run](https://github.com/sansaks-jpg/rustmix/actions/workflows/windows.yml) and download `rustmix-windows-x64`. Extract and run `rustmix.exe`. ## Operate the demo

Seven synthetic inputs are available on launch. Select an input thumbnail to change Preview. Space cuts, Enter fades, and the T-Bar scrubs a manual crossfade. The source exchange commits at completion; cancel returns to the original Program. B fades to black / restores. F1–F4 toggle Program overlays. Text editing suppresses switching shortcuts.

Add Input supports seven procedural types. Per-tile Cut explicitly takes that source to Program. Per-tile 1–4 buttons use its name as a lower-third title, rather than overlaying the full video input. Quick Play cuts the already animating synthetic Preview; Pause Inputs freezes procedural video while transitions remain responsive. Input Edit opens rename, color, type and online/offline properties. Removing Program/Preview or editing sources during a transition is rejected explicitly. Offline inputs render black and stay in the project with a warning.

The source selector now groups seven implemented procedural generators alongside explicitly disabled media/device categories. Input Properties separates General, live simulated Audio routing, and read-only Status; source removal requires confirmation. Settings groups display, appearance, workspace and shortcuts with a draft Apply/Cancel flow for project preferences and layout presets. Checkpoint recovery runs when requested; live simulated audio changes apply immediately. This follow-up UI work still requires new hosted Windows native screenshots and tests before it can be considered verified; previous CI evidence refers to the earlier layout.

Audio strips control gain, mute, solo and Master/Aux A/Aux B assignments. **Meters are deterministic simulations; no audio is emitted.** Bus mute and solo affect simulated bus meters. There is no mix-minus DSP or hardware device backend.

The main layout follows common vMix-style placement: orange Preview, green Program, centered transition stack, inputs below, audio on the right and production controls along the bottom. All code/media/branding remain independent. Drag the lower panel tabs to rearrange, dock or float them inside the main window. Drag dividers and the lower edge of the monitor bank to resize. View restores Production / Audio focus presets. Multiview changes the main monitor area into source tiles. Fullscreen applies to the application window, not a separate video output.

Save / Save As writes versioned `.rustmix.json` project JSON with the panel layout. Open restores it. Files are validated and replaced atomically on the same filesystem; `.bak1` / `.bak2` retain previous versions and `.bak0` is a recovery journal. Existing corrupt projects are not overwritten. File dialogs and disk operations run on a worker so the demo remains responsive. Automatic recovery checkpoints are written every 60 seconds to the user's application data RustMix folder; use Settings → Recover checkpoint. Project files are not silently restored at launch. Window geometry and panel placement are persisted by eframe.

Canvas resolution is a project preference; the UI demo raster is capped at 640×360 and source previews at 384×216. CPU demo generation time and UI callback FPS are measured; they are not broadcast output, encoder, GPU or end-to-end latency metrics.

UI-004 continues the reference-driven operator work: Add Input, Input Properties and Settings now constrain themselves to the viewport, scroll their navigation and content separately, and keep Apply/Cancel outside the scroll areas. Monitor headers open source properties directly. The input bank shows the selected category, matching count, clear-filter action and explicit offline labels. Context-menu removal now uses the same confirmation as Properties. Generator samples are independent of existing inputs. These are source changes awaiting a new hosted compile, widget run and native screenshot review; the downloadable UI-002 executable does not contain them.
